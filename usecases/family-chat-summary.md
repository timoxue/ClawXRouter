# 家庭群聊天记录总结

家庭群里每天几百条消息 — 爸妈的养生链接、孩子的学校通知、七大姑八大姨的生活近况。你一忙错过半天，翻聊天记录又翻不完。想让 AI 帮忙总结？但这里面全是家人的真名、电话号码、家庭住址、健康状况……直接发给云端模型等于把全家隐私交出去。

这个 use case 用 GuardClaw 在本地完成聊天记录解析和去标识化，匿名数据再交给云端大模型生成结构化摘要。

## Pain Point

- 家庭群消息量大，手动回顾耗时
- 聊天记录包含大量 PII：真实姓名、电话、地址、身份证号、银行卡号、健康信息
- 家庭成员的隐私意识参差不齐，经常在群里直接发敏感信息（"我身份证号是……"）
- 云端 AI 摘要服务无法保证这些数据不被训练或泄露

## 工作原理

```
微信/Telegram 聊天记录导出
         │
         ▼
[S3 本地 Guard Agent] ─────────────────────────────────────
│                                                           │
│  ① 解析聊天格式（时间戳、发言人、内容）                     │
│  ② 识别敏感信息：                                         │
│     - 人名 → Person A / Person B（维护映射表）             │
│     - 手机号 → [PHONE-1]                                  │
│     - 地址 → [ADDRESS-1]                                  │
│     - 身份证/银行卡 → [ID-REDACTED]                       │
│     - 健康信息 → 保留症状描述，去除就诊医院和医生姓名       │
│  ③ 提取关键事件清单（匿名化版本）                          │
│     - "Person A 提到下周六有家庭聚会"                      │
│     - "Person B 分享了 [CHILD] 的成绩单照片"               │
│     - "Person C 询问 Person D 的 [HEALTH-CONDITION] 恢复情况"│
─────────────────────────────────────────────────────────────
         │
         ▼ 匿名化事件清单
[S1 云端大模型]
│
│  ④ 按主题分类：家庭聚会 / 教育 / 健康 / 日常 / 待办
│  ⑤ 生成结构化周报/日报
│  ⑥ 提取需要你回复或行动的事项
│
         ▼
    家庭群周报（匿名版） + 待办提醒
```

### 模型分工

| 阶段 | 模型 | 敏感级别 | 说明 |
|------|------|----------|------|
| 聊天记录解析 + 去标识化 | 本地模型（Qwen2.5 7B） | S3 | 全程本地，映射表不离开本机 |
| 事件提取 + 匿名化 | 本地模型（Qwen2.5 7B） | S3 | 输出的事件清单已不含 PII |
| 主题分类 + 摘要生成 | 云端大模型 | S1 | 只看到 Person A/B/C 的匿名事件 |
| 待办提醒生成 | 云端大模型 | S1 | 生成你需要回复/行动的列表 |

## 期待结果与效果预估

> **一句话**：家庭成员 PII 全部留在本地，摘要质量仅损失约 5-10% — 匿名化后云端仍能准确分类话题和提取待办。

### 隐私保护效果

| PII 类型 | 检测方式 | 预估拦截率 |
|----------|---------|-----------|
| 手机号（1xx-xxxx-xxxx） | 正则模式 | ≥ 99% |
| 身份证号（18 位） | 正则模式 | ≥ 99% |
| 银行卡号（16-19 位） | 正则模式 | ≥ 98% |
| 真实姓名 | Local LLM NER | ~90-95%（非常见姓名可能漏检） |
| 家庭住址 | Local LLM + 关键词 | ~85-92%（非标准格式地址较难） |
| 健康信息 | 关键词 + LLM 上下文判断 | ~88-93% |

**残余风险**：昵称、绰号、非标准地址描述（如 "我家楼下那个超市"）可能漏检。但这类信息即使泄露，在没有映射表的情况下也无法关联到具体个人。

### 质量影响预估

| 维度 | 影响程度 | 说明 |
|------|---------|------|
| 话题分类 | **无损** | "Person A 提到家庭聚会" 足以分类 |
| 待办事项提取 | **无损** | 动作和时间节点保留完整 |
| 情感/语气理解 | **略降（~5%）** | 匿名化丢失部分家庭角色上下文 |
| 照片/视频描述 | **略降（~10%）** | 仅靠文字描述，无法传达视觉内容 |

### 成本对比

| 方案 | 本地处理 | 云端摘要 | 总计 |
|------|---------|---------|------|
| 纯云端（无 GuardClaw） | $0 | ~$0.5-2（1000 条消息） | ~$0.5-2 |
| GuardClaw 混合 | ~$0.02-0.10（LLM 检测+脱敏） | ~$0.1-0.5（匿名事件清单更短） | ~$0.12-0.6 |

匿名化事件清单比原始聊天记录短 60-80%，云端处理的 Token 量显著降低，**反而更省钱**。

### 延迟影响

- 1000 条消息本地解析 + 去标识化：~2-5 分钟（7B 模型）
- 云端摘要生成：~10-30s
- **总耗时**：~3-6 分钟（vs 纯云端 ~30s-2min）

### 风险与局限

- 非常见中文姓名的 NER 召回率偏低（如少数民族姓名）
- 引用回复的上下文可能暴露间接 PII（"回复 XX 的消息"）
- 映射表丢失则无法将 Person A/B 还原为真人
- 大量语音消息/图片分享的群无法处理（仅支持文字导出）

## 关键洞察

- **映射表是关键**：本地维护一张 `Person A = 爸爸, Person B = 妈妈` 的映射表，这样你看到摘要时能对应回真人，但这张表永远不离开本机
- **健康信息需特别处理**："Person C 血糖偏高" 这种描述可以保留（匿名后无法关联到具体人），但 "xxx 医院李医生说" 必须去除
- **照片/视频只提取描述**：本地模型标注 "Person A 分享了一张聚餐照片"，照片本身不发给云端
- **对话上下文很重要**：单条消息可能看不出敏感性（"好的"），但结合上下文（回复一条含身份证号的消息）就是 S3
- **Dual-Track Memory**：`MEMORY-FULL.md` 记录带真名的家庭信息方便后续问答，`MEMORY.md` 只存匿名版本
